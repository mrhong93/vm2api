# 备份与恢复

备份页面位于「设置 → 备份」。支持本机备份，以及腾讯云 COS、阿里云 OSS 和 S3 兼容存储。备份先在本机生成，上传后核对对象长度、SHA-256 元数据及可读取的独立索引，成功后再清理本地副本。恢复时会重新下载并计算整个文件的 SHA-256，然后验证解密结果、归档清单及数据库版本。

上传校验没有重新下载整个对象；完整内容的 SHA-256 在下载恢复时核验。请同时使用云服务的数据完整性保护；重要备份可开启桶版本管理或异地复制，并定期在隔离实例演练恢复。

## 备份范围

| 资料 | 处理方式 |
| --- | --- |
| SQLite 数据库 | 使用 `VACUUM INTO` 获取包含已提交 WAL 的一致快照，包含用户、API Key、账号、用量与计费记录、代理、集群登记、配置等数据库状态 |
| 账号池、绑定及登录凭据 | 包含 `data/codex-login-pool/`、`data/codex-mailbox/` 及数据目录顶层持久 JSON |
| 注册记录 | 包含 `data/codex-registration/`，包括未完成流程的持久状态 |
| 质量运维 | 包含 `data/quality-preview/` 和 `data/quality-records/` 中的配置与执行记录 |
| 槽位资料 | 包含 `vms/*.json` 及槽位目录内的持久文件，包括嵌套的 Codex / Claude CLI 授权资料 |
| 浏览器会话 | 包含宿主机挂载目录内 `kin-mailbox/profiles/` 和 `kin-mailbox/config/`；SQLite 逻辑快照保留已提交 WAL，LevelDB 的数据日志保留 |
| 路由等配置 | 包含配置目录顶层 JSON；数据库目录和项目 `data/` 分离部署时，两处持久资料均处理 |
| 部署参考 | 保存项目根目录 `.env`、Compose 文件、`VERSION` 和 `deploy/payload.json`；仅恢复到 `data/restored-deployment/<备份 ID>/`，供人工核对，**不覆盖目标机正在使用的部署配置** |

排除浏览器运行包、依赖、缓存、普通文件日志、临时文件、锁、套接字、面板登录会话、虚拟机磁盘，以及控制面未挂载的集群/容器内部资料。数据库中的请求日志、计费记录随数据库保留。不会跟随符号链接；使用符号链接作为备份根目录时会拒绝操作。

本功能不是跨集群整机镜像。远程节点的独立磁盘、未挂载浏览器目录和外部数据库需要分别备份。浏览器运行环境可按需重装；跨机器或系统密钥环变化后，已恢复的浏览器会话仍可能需要重新授权。

普通在线备份保证数据库快照一致，并拒绝与浏览器任务并行执行；所有后台 JSON 写入与数据库之间并非同一个全局事务。需要严格一致的业务时间点时，应先静置业务、结束后台任务，再手动备份。

## 配置 COS / OSS

在存储桶表单填写以下内容后，先「测试连接」，再保存并启用：

| 项目 | COS 示例 | OSS 示例 |
| --- | --- | --- |
| Endpoint | `https://cos.ap-guangzhou.myqcloud.com` | `https://s3.oss-cn-hangzhou.aliyuncs.com` |
| 地域 | `ap-guangzhou` | `cn-hangzhou` |
| 桶名 | `example-backups-1234567890` | `example-backups` |
| 目录前缀 | `vm2api/instance-a/` | `vm2api/instance-a/` |
| 路径寻址 | 通常关闭 | 必须关闭，使用虚拟主机寻址 |

Endpoint 填写服务地址，不包含桶名、路径或认证信息。使用 HTTPS；仅本机回环测试服务允许 HTTP。不同实例必须使用不同目录前缀：保留份数会清理**当前前缀内**超额的备份。

OSS 使用专用的 S3 兼容入口 `s3.oss-<地域>.aliyuncs.com`，地域填写 `cn-hangzhou` 等地域 ID，遵循[阿里云 AWS SDK 接入说明](https://www.alibabacloud.com/help/en/oss/developer-reference/use-amazon-s3-sdks-to-access-oss)。本实现关闭 AWS 可选流式校验，使用已知长度的普通或分段请求。若桶受新用户公网 Endpoint 限制，请按服务商要求配置可用域名。

使用仅有该桶/前缀权限的专用密钥。需要列举前缀、读取、写入、删除对象，以及创建、上传、完成和中止分段上传的权限；不需要列举所有桶。连接测试会在所选前缀创建、读取并删除一个随机小对象，也测试列举权限。分段上传使用 16 MiB 分段和最多两个并发分段，失败时中止上传。云端可额外配置清理未完成分段的生命周期规则，以处理进程突然中断的情况。

云端备份强制加密，需设置至少 12 位的备份密码。**密码应独立保存于宿主机之外**；仅有存储桶密钥不能解密备份。密码轮换后仍需保留历史密码，恢复旧备份时可在确认框填写原密码。

本机 `data/backup-storage.json` 使用独立的 `data/backup-storage.key` 加密，权限为仅服务用户可读写。接口只返回密钥/密码是否已配置，不回显内容；密钥和密码输入留空时保留原值。这两个配置文件不会被本功能备份，也不会用源机配置覆盖目标机的桶设置。

## 本机空间与保留策略

- 未启用存储桶：按计划中的份数保留本地普通备份，默认每天一次、最近 7 份。
- 启用存储桶：可选「校验成功后立即清理」或「最多保留 24 小时」。上传完成且远端索引可读取后，本地归档才进入清理流程。
- 上传失败或索引未确认：本地文件始终保留，不受正常份数/时间清理影响；服务重启后仍会重试。即使关闭定时备份，也会继续清理到期缓存和重试上传。修改桶或前缀后，不会把原失败备份自动传到另一个目的地。
- 远端普通备份按配置份数保留；恢复前快照额外保留最近 3 份。超额远端归档被清理时，会同步清理该份本地缓存，因此 24 小时是本地保留上限。
- 「清理本地」只删除选中的本地副本，已经上传的远端备份仍可扫描恢复。未成功上传的唯一副本被人工清理后无法恢复。
- 维护任务默认每 10 分钟检查一次，24 小时缓存会在到期后的维护周期清理。正常任务及时删除暂存明文和下载文件；识别出的异常遗留暂存资料超过 24 小时后清理。恢复失败的回滚证据不会被自动清理。

不保留本地副本也需要暂存空间。创建期间需要数据库/持久文件快照及打包文件空间；加密期间还会短暂同时存在压缩包和密文。恢复需要下载文件、解包暂存、旧文件回滚副本、旧数据库，以及恢复前备份所需空间。可用 `KIN_BACKUP_TMPDIR` 将临时目录放在更大的磁盘；备份目录和持久资料目录仍须有足够空间。

纯本地 `.tar.gz` 备份未加密，包含授权资料及源数据库解密密钥，必须按密码资料保管；上传已有本地完整备份时先加密。旧版 `.db.gz` 仅包含数据库，不能补回当时未打包的文件。

## 扫描与恢复

1. 先结束所有登录、注册、浏览器接管与后台任务，**关闭全部槽位**。仅关闭调度不足以允许恢复。
2. 本机有副本时，在记录中选「恢复」；否则在「从存储桶恢复」点击「扫描存储桶」，按时间选择备份。列表分页加载，显示不可读取/不完整的索引。
3. 确认恢复，必要时填写该归档的原加密密码。系统下载并校验完整 SHA-256，检查解密认证、路径、文件清单、数据库完整性、迁移兼容性及凭据解密。
4. 预检通过后进入维护状态，暂停请求和后台任务，先创建恢复前快照，再替换数据库与选定持久文件。新建但备份时不存在的选定文件会被移除；被排除的运行包与缓存保留。
5. 重新绑定计费、账号、代理、配置等运行中的存储引用，恢复后台服务。恢复出的槽位保持关机；检查目标机路径、代理、集群连接和部署参考后，再手动开机。

**全新实例不需要原机的备份记录。** 安装兼容版本，填写原桶、前缀、访问密钥和备份密码，即可扫描并恢复。归档携带源凭据密钥，恢复时重加密为目标实例密钥；目标未设置数据库密钥时生成并持久保存 `data/credential-secret.key`。旧版不含源密钥的备份，需沿用当时的数据库密钥。

错误密码、损坏内容、不安全路径、链接或不兼容数据库会在替换前拒绝，不创建恢复前快照，也不改动当前业务资料。迁移成功后不保证旧程序能直接打开新数据库；回退程序时应恢复与其匹配的备份。

## 中断或失败后的人工恢复

正常错误会自动回滚数据库与文件；回滚或恢复后台服务失败时，服务保持维护状态，并保留 `data/backup-restore-pending.json`、旧数据库及文件回滚日志。发现这个标记时，正常启动会拒绝打开数据库。**不要直接删除标记后尝试启动，也不要清空临时目录。**

人工处理必须在服务和相关写入进程已停止时进行：

1. 保留当前数据库及 `-wal` / `-shm`、`data/`、`vms/`、`config/`，以及标记中指向的整个临时目录的副本。确认标记中的路径属于本次恢复和正确实例。
2. 标记的 `saved_database` 若仍存在，这是替换前已关闭的旧数据库。先按 `rollback_directory/journal.json` 逆序恢复文件，再用旧数据库替换 `database`；替换前移走当前数据库及其 WAL/SHM。项目中的 `rollbackState(journal)`（`src/lib/admin/backup-layout.mjs`）用于重放该日志，会恢复原文件内容、权限及所有者，移除本次新建的文件。
3. `saved_database` 不存在时，可能尚未发生数据库替换，也可能自动回滚已经成功、仅后台恢复失败。核对当前数据库、文件日志和服务日志；**不能仅凭文件缺失断言恢复成功**。缺失或损坏的日志不能强行重放，应使用恢复前归档在隔离实例验证后恢复。
4. `key_created` 为真且选择回到恢复前状态时，核对并移走本次创建的 `data/credential-secret.key`；保留原环境变量/密钥配置。不要移走原来就存在的凭据密钥。
5. 离线检查数据库完整性、版本、账号凭据可解密及配置/绑定对应关系。确认文件与数据库属于同一恢复时间点后，归档而非直接销毁维护标记，再启动服务；槽位保持关机并检查后台服务。验证完成后才清理旧数据库、回滚目录和事故副本。

若仅存储桶配置密钥丢失，停止服务并保存原 `backup-storage.json` 与 `backup-storage.key`，将它们移到受保护的故障资料目录，再启动并重新配置桶。此操作不删除桶内备份；恢复历史归档仍需要原备份密码。

## 离线验证

`test/unit/backup-complete.test.mjs` 覆盖完整往返、分离目录、空范围、0/24 小时清理、失败重试、空记录异机恢复、密钥迁移、损坏/恶意归档、版本预检和回滚。`backup-storage.test.mjs` 使用回环 S3 服务验证真实 SDK 签名、分页、下载校验及分段失败中止；`backup.e2e.test.mjs` 验证面板权限、脱敏、上传清理和恢复后计费/路由重绑定。所有账号、密钥和推理结果均为离线虚构夹具，不调用实际模型。

- Windows / Node 22 与禁用外部网络的独立 Linux / Node 22 容器：备份、存储、恢复隔离、浏览器任务互斥及面板端到端测试合计 64 项分别通过。Linux 容器不挂载实际业务目录或 Docker socket，仅使用虚构数据与回环 S3 服务。
- 前端：68 个测试文件、516 项测试通过；格式检查、TypeScript 检查和生产构建通过。
- 独立测试实例已完成页面及接口验收，核对的业务表行数与持久目录挂载未变；保留升级前容器及受保护的回退资料。开发验收未执行实际账号登录、模型请求或对现有业务数据的恢复。
- 完整 Linux CI 是 PR 合并与正式发行的门禁，覆盖 Node、Go、离线浏览器夹具、前端和离线备份端到端测试。Windows 默认 Node 25 的全量测试含 Linux 套接字、权限和 shell 依赖，不能代替 Linux CI。
- 自动化存储验证使用回环 S3 夹具，不表示真实 COS / OSS 全面联测；实际云服务的地域、权限、兼容入口及网络策略需在部署环境核对。
