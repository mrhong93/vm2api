# 槽位浏览器环境管理

## v2.4.0 状态核验

面板显示 Playwright 版本及运行包修订号（如 `1.64.1 · r4`），并检查图形二进制的执行权限。旧包或组件不可执行时明确提示升级；登录缺少有效显示地址时停止。控制面升级与槽位运行包升级是两个步骤，升级保留 profiles、缓存和配置。

图形运行包的构建和安装修复自 v2.1.2 已进入公开镜像；本次直接检查 v2.1.2、v2.3.0 amd64 镜像中的 7 个关键文件，均与相应 Git 标签一致。大型运行包通过安装按钮按匹配系统构建、校验和缓存。确认 r4 图形模式后仍反复遇到 CF 验证，应结合实际出口、网络和会话排查，不能仅凭循环验证认定组件未发布。

## v2.1.2 图形运行包升级

旧 r3 包没有包含标准图形环境。更新控制面后，在槽位详情点击“升级浏览器环境”，安装 r4 包；仅更新镜像不会替换已有浏览器包。图形组件从匹配发行版的官方源码构建，并以槽位用户运行，不写入只读系统目录。安装前使用相同显示模块在临时目录验证图形启动、截图及点击，失败不覆盖旧包。卸载包含图形组件，profiles、缓存和配置仍保留。

Docker 登录、注册和远程浏览器任务开始前检查实际容器内存上限：有限配额至少 1 GiB；无限配额不按 0 内存处理。请通过槽位概览显式提升资源，程序不自动扩容或开启调度。此要求为浏览器运行预留空间，不代表任何网页负载下都不会耗尽内存。

图形显示使用私有 X11 认证并关闭 TCP 监听，无需完整桌面。远程屏幕在接管前只读，完成网页人工步骤后再继续自动流程。浏览器环境正常和输入成功，不等于第三方人机验证必定通过。

远程屏幕支持文字剪贴板：先在槽位网页点击「复制」，再点面板「读取远程剪贴板」，内容会显示在只读文本框中；「复制到本机」支持 HTTPS Clipboard API，也支持内网 HTTP 的选中复制回退。复制失败时可直接在文本框按 Ctrl+C。关闭屏幕、切换槽位或浏览器任务结束会清除面板显示；不写入本地存储、账号池或任务状态，也不自动读取。仅在手动浏览器或已接管的任务中允许读取，限制为支持的登录站点和 16 KiB 文字。首次启用本功能需重新打开槽位浏览器；不会清除浏览器 profile。

GPT 槽位详情页的「安装浏览器环境 / 卸载浏览器环境」只管理运行文件，不执行账号登录、OAuth 或首次登录解锁。无需绑定账号凭据。槽位必须已运行，无需开启调度，也不会修改调度开关；关机或显式取消会中止维护。维护与登录、远程浏览器共用互斥锁。

安装根据**实际槽位**的 `/etc/os-release`、CPU 架构和系统 Python 版本选择运行包，不根据面板机系统猜测。支持 Ubuntu 22.04（Python 3.10）、24.04（3.12）、Debian 12（3.11）、13（3.13），架构 amd64 / arm64；自定义 Python ABI 不匹配时拒绝安装。实际测试范围另行记录，支持矩阵不代表所有组合均已实测。

面板使用目标 Docker 节点上的临时 builder 下载固定版本 Playwright 1.64.1、Chromium、字体和动态库，并构建图形显示组件，生成匹配系统的包，缓存到面板 `share/kin-mailbox-runtime/managed/`。首次源码构建会下载编译依赖，需要较长时间；这些依赖留在可销毁的 builder，不安装进槽位。缓存通过 SHA-256 校验，同一系统组合可复用。远程节点目前仍通过面板传输运行包，尚未实现节点共享浏览器目录。临时下载代理 `VM2API_BROWSER_BUILD_PROXY` 仅传入 builder，不设置槽位代理；不要把带密码的代理写进公开配置。

运行文件安装到槽位 `/home/kincli/.local/share/kin-mailbox/`，不修改只读系统根目录。全新临时目录内先以槽位用户启动 Chromium，使用内存 HTML、临时 profile 并拦截网页请求，检查成功才替换旧运行文件。失败或取消保留原环境。整个安装过程不读取账号凭据或现有 profile，也不访问登录页面。

卸载仅移除浏览器、venv、依赖库等运行文件，保留 `profiles/`、`cache/`、`config/` 和独立存放的账号凭据。升级/重装也保留这些目录。识别到旧 `/opt/kin-mailbox` 环境时会尝试卸载其运行文件，若镜像目录只读则明确报错。卸载后点击登录会提示先安装环境，不再自动下载。

API（沿用面板认证、角色和槽位所有权检查）：

- `GET /api/panel/vms/:id/oauth/login/browser-environment`：只读检测，不启动浏览器。
- `POST .../browser-environment/install`、`POST .../browser-environment/uninstall`：返回 202，轮询上面的状态接口查看结果。

专用测试容器的集成验证（不得指向真实账号槽位）：

```sh
sudo python3 test/manual/mailbox-portable-test.py \
  --image <匹配系统且已安装python3的测试镜像> \
  --bundle <对应系统的r4运行包.tar.gz> \
  --work-dir /var/tmp
```

脚本创建并清理随机命名的专用容器，使用 `network=none`、只读根目录、`cap-drop ALL`、UID 10005、0700 home 和 1 GiB 内存；验证图形浏览器启动、语言时区、iframe 远程点击和截图、重装保留资料、损坏包及启动失败回退、槽内取消、卸载和重新安装，全程无账号登录。必须在专用 Linux 测试主机执行，不指向现有槽位。`--work-dir` 必须位于磁盘文件系统；将近 1 GiB 的安装文件存入宿主机 tmpfs 会占用容器共享内存配额，导致测试失真。

2026-10-27 的 r4 实机验收：Ubuntu 24.04 / Python 3.12 / amd64、Debian 12 / Python 3.11 / amd64 均通过上述完整流程。新包压缩后分别约 426 MiB、423 MiB，构建时复用既有 Chromium 文件，但图形组件、依赖收集和打包均由本版构建脚本重新执行。未访问真实登录站点或执行人机验证。其他系统版本、arm64、KVM 和远程集群尚未实机验证。

历史验证：2026-10-26 的 r3 包在隔离测试机通过 Ubuntu 24.04 / Python 3.12 / amd64 和 Debian 12 / Python 3.11 / amd64 的无头安装检查、普通槽位用户 prepare、面板 HTTP 安装/卸载和未认证拒绝。这不等于 r4 图形环境验收。r4 的逐项实机结果在发行说明记录；其他系统版本、arm64、KVM 和远程集群尚未实机验证。
