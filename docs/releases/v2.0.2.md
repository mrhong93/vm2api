# vm2api v2.0.2 · 槽位注册自动化与智能运维

**让账号准备有流程，让运行环境可复用，让质量判断可追溯。**

本版基于上游 **v1.3.226**，延续独立维护的版本、更新源与发布链路。围绕账号生命周期，打通槽位浏览器环境管理、注册辅助、人工接管和凭据入池，并带来全新的智能运维工作区。

## 注册自动化：把环境一致性贯穿整个流程

- **指定邮箱，生成随机强密码。** 适配邮箱验证码直登后的设置密码流程，再进入 2FA 配置；邮箱验证码与验证器验证码分别处理。
- **确认成功才入池。** 密码设置与 2FA 启用均得到明确确认后，才保存到加密凭据池、绑定当前槽位并尝试 OAuth 授权。网页登录成功不会被误判为授权成功。
- **全过程沿用当前槽位环境。** 浏览器语言、时区、持久会话与网络出口来自所选槽位；保持出口一致性检查，避免控制面环境混入账号流程。
- **自动处理常规步骤，远程接管复杂页面。** 支持远程屏幕、鼠标键盘和文字剪贴板；遇到人工验证、额外邮箱验证、手机验证或未知页面，可由操作者接续完成。验证码和手机验证仍需人工处理，不承诺无人值守注册。
- **中断可恢复，凭据有保护。** 在关键提交前加密保存恢复信息；只有显式查看才返回明文，TOTP 在本地计算，不把密钥交给第三方验证码网站。

## 浏览器环境：按槽管理，安装与账号操作分离

- 面板提供安装、重装、卸载入口，识别槽内 Ubuntu / Debian、CPU 架构及 Python ABI，选择匹配的运行包。
- 运行包缓存复用并校验 SHA-256；临时环境验证启动成功后才替换，重装和卸载保留浏览器会话资料。
- 空槽可以先开机准备环境；手动注册、登录和维护无需开启业务调度，关闭调度时仍不执行自动重登和接单。
- Ubuntu 24.04 / Debian 12 的 amd64 环境已做隔离验证；其他支持组合、ARM64 浏览器运行包和跨节点环境仍需按实际部署验证。远程节点运行包目前仍经控制面传输。

## 智能运维：统一入口，规则透明

- 原账号池升级为 **智能运维**，集中提供 **账号凭据 / 质量运维** 两个工作区。
- 账号与槽位合并选择，检测模型读取对应平台的受支持目录，频率统一为可输入的整数分钟。
- 糖果题保留 sub2 v2.17.3 原文，可编辑、恢复原文并按任务持久保存到服务器；刷新不丢失，版本校验防止多页面覆盖。
- 默认以 **回答包含独立数字 21** 判为通过，支持完整解释，排除 121、210、21.5 等误匹配；无需额外裁判模型，详情展示完整回答供人工复核。
- **本版质量运维为配置与判定演示预览。** 真实定时检测、自动处置及 sub2 门票探针尚未接入；演示记录不是实际模型质量结论。运行真实糖果检测仍需调用被测模型，“无需裁判模型”仅指结果判定。

## 工程保障

加密存储、用户权限隔离、任务互斥、失败恢复、浏览器离线页面夹具、网络冲突检查与前端构建纳入验证。注册夹具拦截上游请求，不使用真实账号。CI 通过后才构建发布产物，多架构镜像及附件齐备后才公开版本。

出口网络使用显式地址池并避开已有 Docker 网络及宿主路由；站点专属保留网段通过私有环境变量 `KIN_EGRESS_RESERVED_CIDRS` 配置，公开源码不携带部署拓扑。

## 获取与升级

镜像：`ghcr.io/zhang2580384/vm2api:v2.0.2`，控制面提供 amd64 / arm64。槽位 kernel / CLI 延续固定 payload，本版不重新替换这些基线产物。

升级前备份 `.env`、`data/`、`vms/` 和原有加密密钥；如使用站点保留网段，先配置 `KIN_EGRESS_RESERVED_CIDRS`。浏览器环境需要在目标槽位按需安装，控制面镜像不内嵌每种系统的完整浏览器运行包。发布不会自动升级你的生产部署。
