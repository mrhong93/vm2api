# v2.2.0 · 质量运维真实检测与调度恢复

质量运维从配置预览升级为真实执行：指定账号与槽位、选择受支持模型，即可立即检测或按分钟定时运行，保存完整回答和处理记录。糖果题与双请求门票探针提供不同角度的检测结果；独立的调度恢复开关，使账号暂停接单后仍能继续接受检测，并在符合条件时恢复接单。

## 真实检测、独立执行、完整留证

- **立即检测一次**发送真实请求，显示执行进度与最终结果；任务配置、频率、题目、GPT 思考强度和完整回答持久保存，详情支持全文复核。
- **糖果题**保留 sub2 原题，允许修改并保存；按独立数字 **21** 判断，无需额外裁判模型。121、210、小数和负数不算命中。此规则也会接受否定句中出现的 21，使用者应结合完整回答复核；可选择严格简短答案模式。
- **门票探针**保留 sub2 的两次完整请求、路由 Cookie 和新票判据，在指定 GPT OAuth 容器槽位内执行。传输层适配槽内 Python 与系统 TLS，并非完整复制 sub2 的 Go TLS 指纹。它提供经验性质量信号，不承诺固定模型档位。
- **按分钟定时**独立于槽位接单调度，暂停接单仍继续执行已启用的质量任务。同账号任务互斥、全局限制并发；重启后延续检测节奏，不补发积压请求。

## 调度关闭与恢复形成闭环

选择“检测不通过时关闭槽位调度”后，只有明确检测不通过，且任务配置、权限、账号和出口仍符合条件时才关闭调度。网络错误、空回答、不完整流和无法判断的结果均不作为关闭依据。

糖果题任务新增独立开关 **“检测通过后自动恢复调度”**。例如每 10 分钟检测一次：检测不通过后暂停接单，10 分钟后的检测仍会进入原槽位；检测通过后，只恢复同一任务实际关闭的调度。人工关闭、其他任务关闭、不可调度故障及维护状态不会被自动清除。任务不自动开机或登录，执行前槽位须已开机且授权可用。

## 升级说明

面板左上角版本链接改为本仓库的 Releases 列表，避免开发版或尚未发布的版本标签返回 404。

1. 更新到 `ghcr.io/zhang2580384/vm2api:v2.2.0`，或通过本仓库的面板更新源升级。
2. 进入“智能运维 → 质量运维”，确认账号与槽位、模型、检测方式、频率及处置开关。
3. **旧配置预览任务需要显式重新启用**，避免升级后未经操作者确认就产生真实请求；原题目与配置保留。建议先“立即检测一次”，检查记录后启用定时执行。
4. 检测会实际消耗账号额度。糖果题进入正常转发计费链路；门票探针直接在指定槽位执行，其用量记录于质量记录。

升级沿用现有数据目录，无数据库结构迁移。回退前请备份质量任务、记录和槽位调度配置；旧版本不具备本版的任务归属恢复逻辑。详细判据、限制与操作见 [质量运维文档](../OPERATIONS_PREVIEW.md)。
