## 保留自有功能

加密凭据池与绑定、槽位注册辅助、密码与 2FA 恢复记录、远程屏幕及剪贴板、Ubuntu/Debian 浏览器环境管理继续保留。浏览器始终使用当前槽位的语言、时区和网络；验证码仍需用户参与，未承诺无人值守注册。

关闭调度仍允许在已开机槽位手动注册、登录与维护浏览器。后台任务继续静置；明确授权成功只清除凭据故障，不自动开启人工关闭的调度，也不抹除代理或维护故障。

智能运维继续支持账号与槽位联选、模型选择、分钟频率、自定义题目持久化、独立数字 21 规则及完整答案展示。**质量运维仍是配置预览，实际定时检测、门票探针和自动处置尚未接入**，不宣称完整移植 sub2api。

保留 #665 按账号唤醒及本分支的有界广播修复、出口地址池与保留网段配置、更新入口和社区二维码。QQ群 **1126616545**，群内基友共同维护。感谢上游及原贡献作者，保留 LICENSE 和来源记录。

## 升级与回退

先在测试环境验证，再安排生产升级；镜像固定版本或摘要。升级前备份数据库、`vms/`、配置、Compose 和旧镜像信息，不覆盖 `.env`、账号、浏览器资料或路由配置。四态调度迁移会保存 `backups/schedule-migration-<时间>/`；完整回退仍应使用升级前一致性备份。

跨基线升级需要同步前后端及匹配的 payload。`restart=no` 迁移失败会阻止控制面启动，需检查 Docker 权限和日志；不要直接在生产重启 Docker 来试验。恢复旧版本时同时评估容器重启策略与出口恢复顺序，不能仅替换一个版本文本。

内网站点通过私有环境配置 `KIN_EGRESS_RESERVED_CIDRS`。源码及公开发布材料不包含站点账号、代理认证、私有地址或浏览器数据。
