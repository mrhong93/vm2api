本版从 **v1.3.226** 选择性同步 **v1.4.006** 的调度与稳定性修复，保留双方 Git 历史。Claude 出站协议和 payload 继续使用本分支 v2.0.2 的兼容实现；不宣称与上游完整等价。自维护版本继续使用 2.x 编号、`zhang2580384/vm2api` 更新源和镜像。

## 同步上游

- 统一调度开、调度关、不可调度、受限四类状态，区分人工决定、确定性故障和临时限制。
- 优化会话亲和及席位释放；GPT 内核重载等待旧进程退出并采用当前代理。
- 本地 SOCKS 槽位使用 `restart=no`，控制面先恢复出口与阻断规则再启动槽位，减少 Docker 重启后的直连窗口。
- 同步额度恢复、删除槽位时清理账号池、域名转发、ARM64 安装和运行目录权限修复。
- 保留原 Claude 协议及 `payload-2026.10.24-cli-303-sdk`，以 `deploy/payload.json` 的尺寸及 SHA-256 为准。

## 暂缓的新协议及原因

主要涉及 Claude：零注入语义、official_303 预设迁移、提示词与环境分段、缓存断点及图片历史改写、thinking/effort、beta 与 cc_entrypoint、auto 模型策略及 count_tokens 接口移除均暂缓。GPT 内核代理重载、额度恢复等独立修复照常同步。

原版上游的相关协议测试仍存在实现与契约不一致；现阶段直接上线会同时改变已有配置与请求形态。我们保留旧行为并观察后续修复，不以删除断言或批量修改预期取得通过。逐项理由、历史复测证据及重新合入条件见 [同步验收记录](../UPSTREAM_SYNC_1.4.006.md)。

## 保留自有功能

加密凭据池与绑定、槽位注册辅助、密码与 2FA 恢复记录、远程屏幕及剪贴板、Ubuntu/Debian 浏览器环境管理继续保留。浏览器始终使用当前槽位的语言、时区和网络；验证码仍需用户参与，未承诺无人值守注册。

关闭调度仍允许在已开机槽位手动注册、登录与维护浏览器。后台任务继续静置；明确授权成功只清除凭据故障，不自动开启人工关闭的调度，也不抹除代理或维护故障。

智能运维继续支持账号与槽位联选、模型选择、分钟频率、自定义题目持久化、独立数字 21 规则及完整答案展示。**质量运维仍是配置预览，实际定时检测、门票探针和自动处置尚未接入**，不宣称完整移植 sub2api。

## 升级与回退

先在测试环境验证，再安排生产升级；镜像固定版本或摘要。升级前备份数据库、`vms/`、配置、Compose 和旧镜像信息，不覆盖 `.env`、账号、浏览器资料或路由配置。四态调度迁移会保存 `backups/schedule-migration-<时间>/`；完整回退仍应使用升级前一致性备份。

跨基线升级需要同步前后端及匹配的 payload。`restart=no` 迁移失败会阻止控制面启动，需检查 Docker 权限和日志；不要直接在生产重启 Docker 来试验。恢复旧版本时同时评估容器重启策略与出口恢复顺序，不能仅替换一个版本文本。

内网站点通过私有环境配置 `KIN_EGRESS_RESERVED_CIDRS`。源码及公开发布材料不包含站点账号、代理认证、私有地址或浏览器数据。
