# v2.4.0 · 代理批量运维与图形环境核验

本版把代理域名转发从逐条编辑扩展为批量运维，并让浏览器运行包版本和图形环境状态更容易核对。保留 v2.3.0 的完整备份、COS / OSS / S3 扫描恢复，以及账号池、槽位注册登录、远程接管、剪贴板和质量运维能力。

## 代理批量编辑

在「代理」列表勾选多条，或「全选当前筛选结果」，点击「批量编辑」即可统一开启或关闭域名转发。跨筛选保留选择并显示筛选外数量，确认窗口展示目标范围、原设置、目标设置及涉及的槽位数。

操作逐条执行，设置相同的代理自动跳过；失败后继续处理其余代理，逐条显示原因，并支持单独重试未成功项。后端重新应用相同开关时会确保出口进程就绪，健康且配置匹配的进程继续复用。批量请求仅提交 `domain_forward`，原有入口、端口、账密、绑定和调度配置保持原值。

搜索覆盖已满、禁用和失效节点，列表增加域名转发标记。本地出口不参与批量选择。域名转发由同一代理按 DNS 关联处理目标地址，不强制 IPv6；应用变更会短暂中断对应出口的现有连接，建议空闲时操作。详见 [批量编辑说明](../PROXY_BULK_EDIT.md)。

## 浏览器环境版本与升级

环境状态显示 Playwright 版本及运行包修订号，例如「图形模式 · Playwright 1.64.1 · r4」。旧包明确提示单独升级，图形显示二进制缺少执行权限时也标记需升级。登录使用图形模式，缺少有效显示地址时明确停止，防止异常显示环境被当成可用浏览器。

图形运行包的构建和安装修复已在 **v2.1.2** 正式发布。本次直接核对公开的 v2.1.2、v2.3.0 amd64 镜像层，运行包构建、显示管理、槽内安装、登录脚本及对应管理模块等 7 个关键文件均与发布标签一致。

控制面镜像携带构建和安装代码；大型 Chromium / Xvfb / 键盘工具及依赖由安装按钮在匹配系统的临时 builder 中生成 r4 包，再校验并安装到槽位。**升级主程序后，已有槽位的旧运行包仍需单独升级。**

升级步骤：

1. 更新控制面至 `ghcr.io/zhang2580384/vm2api:v2.4.0`。
2. 查看槽位浏览器环境。提示需升级时点击「升级浏览器环境」，等待安装检查通过。
3. 确认显示「图形模式」及 r4；重新开始登录并接管远程屏幕，完成站点要求的人工步骤。

重装或升级保留浏览器 profiles、缓存和配置。详细支持矩阵和资源要求见 [浏览器环境说明](../BROWSER_ENVIRONMENT.md)。

CF 验证反复出现不能仅凭现象归因于缺少组件。图形环境就绪、鼠标输入成功和站点接受验证是不同结果；本版不承诺 CF 验证通过。已确认 r4 图形模式的失败样本还需结合实际出口、网络稳定性和会话状态排查。

## 验证及兼容范围

- 代理批量操作覆盖顺序执行、设置相同跳过、本地出口排除、失败继续、单项重试、关闭开关及请求字段限制。
- 浏览器回归覆盖缺少显示地址时拒绝启动；Debian 12 / Python 3.11 / amd64、Ubuntu 24.04 / Python 3.12 / amd64 使用 r4 包验证图形启动、截图、iframe 点击、权限异常识别、重装保留资料、失败回退、取消和卸载重装。
- 完整 CI 检查 Node / Go、离线账号流程、备份恢复及前端格式、测试和构建。实机浏览器验证使用独立容器、虚构数据、禁用网络，不登录真实账号或调用实际模型。其他系统、arm64 浏览器运行包、KVM 和远程集群未新增实机验收。
