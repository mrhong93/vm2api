# v2.1.2 · 图形浏览器运行包与只读槽位兼容修复

此前“浏览器环境已安装”只验证了无头 Chromium，标准运行包没有包含测试环境额外准备的图形组件。安装检查通过，并不代表远程人工操作使用了相同的浏览器模式。本版把这部分正式纳入开源构建、安装、验证和卸载流程。

## 可移植图形运行环境

新增 r4 运行包，包含 Xvfb、xkbcomp、键盘数据、依赖库及共用显示管理模块。Xvfb 从目标 Ubuntu / Debian 的官方包源下载源码构建，通过标准构建选项和进程内 PATH 查找槽位自己的键盘工具，不依赖向只读 `/usr/bin` 写入文件。安装前的临时目录和正式安装目录均可运行。

显示服务与浏览器使用当前槽位的用户、语言、时区和出口网络。显示服务禁止 TCP 监听，使用私有认证文件；无需完整桌面、宿主机浏览器、开放 VNC 端口或放宽容器权限。

安装使用独立临时 profile 和内存测试页，拦截外部网页请求，验证图形 Chromium 启动、截图及点击后才替换旧环境。安装不执行账号登录；重装保留 profiles、缓存和配置，卸载同时移除图形组件并保留账号资料。

## 升级操作与资源要求

1. 更新控制面到 `ghcr.io/zhang2580384/vm2api:v2.1.2`。
2. 在槽位详情点击“升级浏览器环境”。旧 r3 缓存不会复用；首次需要下载和编译，后续同系统组合复用 SHA-256 校验后的缓存。
3. Docker 槽位的实际内存上限需至少 **1 GiB**，否则任务开始前明确提示提升。资源不会自动调整；KVM 仍由其独立资源配置管理。
4. 重新开始登录，连接远程屏幕并点击“接管鼠标键盘”后操作网页。只读状态会显示提示，聚焦屏幕不会改变页面滚动位置后再计算点击坐标。

升级主程序不等于替换已经安装的浏览器运行包。旧环境缺少组件时会明确报错，不继续静默使用无头模式。无需重建槽位或清除浏览器会话。

**本版修复浏览器环境一致性，不保证 Cloudflare 或其他第三方验证通过，也不包含验证绕过功能。人机验证、手机验证仍由操作者完成。**

## 验证与兼容边界

回归检查覆盖运行包缓存升级、实际 Docker 内存限额、显示认证和清理、前后端测试与离线账号流程。独立 Linux 集成验证使用虚构资料，不登录真实账号。安装支持矩阵继续为 Ubuntu 22.04 / 24.04、Debian 12 / 13 和 amd64 / arm64；逐项实机范围及操作说明见 [浏览器环境文档](../BROWSER_ENVIRONMENT.md)，不能把支持矩阵视为所有组合均已实测。
