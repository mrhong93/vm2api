# 智能运维配置预览

测试入口：`/cc#/credentials?tab=quality`。账号凭据连接原凭据 API，质量运维使用左任务、右记录、右侧编辑抽屉。

账号与槽位合为一个下拉框：优先展示绑定凭据的邮箱，其次槽位邮箱，空槽不可选。模型读取 `/api/panel/test-models?vm_id=...`，与现有受支持模型目录一致，切换槽位清空模型选择；不使用 refresh，不调用上游或刷新账号令牌。目录中的支持不保证某个账号当时可调用成功。

任务通过已鉴权的 `GET/PUT /api/panel/quality-preview` 按面板用户持久保存到 `data/quality-preview/`，临时文件原子替换，revision 防止多页面覆盖。保存任务名称、账号显示名、槽位 ID、模型、原样题目、判定方式、整数分钟频率及预览开关/动作。没有密码、令牌或 2FA。读取失败不会自动覆盖成空配置。新目标校验槽位可见性与模型目录；记录仍是明确标注的演示数据，不持久保存。

糖果题默认逐字采用 sub2 v2.17.3 `backend/internal/service/pelican_scheduled.go` 的 `CandyPrompt`。编辑后按任务保存，不追加任何提示词；恢复原文按钮只修改编辑草稿，点击保存才生效。答案仍固定为 21，改变题目含义需配套改变判定（尚不支持自定义正确答案）。默认采用包含独立数字 21 模式，支持带解释的完整回答，详情展示全文。可选的严格简短答案规则参考 `candy_answer.go`；包含独立数字 21 模式是本项目按用户要求增加的，否定句中出现 21 也可能通过，不能声称与 sub2 完全一致。

**探针尚未移植。** 原预览的“HTTP 200 / OK”仅用于演示，并非 sub2 算法。sub2 `openai_codex_state_probe.go` 先无票请求取 `x-codex-turn-state` 及路由 Cookie，再携票续接；两次 HTTP 200 且流完整才判断，续接有不同新票视为疑似降级，没有新票或原票视为正常，失败归为无法判断。它还有账号类型/模型限制、并发保护、超时和错误分类。此判据是 sub2 项目推断，不代表服务方质量保证。

当前不执行真实探针、糖果检测、定时任务或调度变更。配置中的启用和异常动作仅预留；演示记录不能作为真实质量证据。配置保存与判定演示已在隔离测试环境验证，发布不等于自动部署或启用检测。
