# 槽位账号注册

在 Codex 槽位登录按钮后点击“注册账号”，输入指定邮箱。系统生成包含大小写、数字、特殊字符及 192 位随机数据的 GPT 密码；密码不使用账号导入分隔符。

流程使用当前槽位的 Chromium、浏览器持久配置、语言、时区、代理和网络出口。只允许已运行、有指定代理且没有账号授权或绑定凭据的空槽开始注册。空槽无需账号凭据即可开机；没有凭据时只启动槽位环境，不启动转发内核。注册、登录和浏览器安装维护共用任务锁。

开机和调度是独立状态。调度关闭时允许显式注册、手动登录及浏览器维护，操作完成不会自动打开调度。自动刷新、自动重登和接单仍要求开启调度。手动任务若在调度关闭时开始可以完成；任务开始后观察到调度开启再关闭则取消，关机、取消或更换绑定也会中止。静置时远程屏幕仅可接入已有的手动注册或登录任务。

1. 开始前先加密保存邮箱和随机密码。
2. 从官网提供的注册或统一登录入口填写邮箱，等待用户输入本次邮箱验证码。未注册邮箱可能直接创建没有密码的账号；网页登录成功不等于密码已设置，也不能单凭会话证明是新账号。
3. 如需验证码接管、个人资料、生日或手机验证，用户通过远程屏幕完成后继续自动流程；系统不生成个人资料。
4. 无密码路径登录后进入账号设置，点击添加、设置或修改密码。按官网需要再次输入邮箱验证码，填写已保存的随机强密码和确认密码，等待官网明确显示设置成功。若要求旧密码、页面未知或没有成功确认，暂停接管，不将生成的密码视为可用。旧版先填密码再验证邮箱的注册页面仍兼容。
5. 密码确认后进入安全设置。若绑定 2FA 要求再次验证邮箱，单独等待本次新验证码；邮箱验证码与验证器 TOTP 分开处理。读取官网验证器设置密钥，先加密保存密钥，再提交根据该密钥生成的 TOTP。必须收到官网明确启用确认，并核对登录邮箱。
6. 密码和 2FA 均确认完成才加密加入账号池并绑定当前槽，随后执行 OAuth。只有 OAuth 成功且调度开启才允许失效后自动重新授权。授权完成后由用户按需开启调度。

注册记录可重新打开。点击查看后可以复制 `邮箱----密码----2FA秘钥` 或单独复制 2FA 密钥。状态接口不返回密码或密钥；明文仅经需要权限的显式查看接口提供，不写入浏览器本地存储或查询缓存。

## 中断恢复

恢复草稿位于 `data/codex-registration/vm-ID.json`，使用现有 DB 密钥加密。目录权限 0700，文件权限 0600，以临时文件和原子替换保存。需备份数据和原有加密密钥。

未完成时保留同一邮箱的随机密码，不自动换密码或重复后台注册。已提交邮箱后不能改邮箱覆盖该草稿。密码写入前保存 `password_submitted`，官网确认后保存 `password_set` 和 `password_verified`，恢复时已确认的密码不重复修改。仅生成密码、提交表单、拿到网页会话均不算无密码路径的密码设置成功。密码或 TOTP 尚未由官网确认时不会入池。旧草稿缺少密码确认标记不会直接入池；如已记录 MFA 完成则需人工核对恢复。若重试发现 MFA 已启用而不能证明保留密钥有效，暂停让用户检查或重新设置。OAuth 失败保留已确认的凭据和绑定，可以手动点击登录重试。

远程屏幕为 Chromium 截图及输入控制，不是完整桌面。关闭注册对话框不会停止任务；“停止任务”才会取消。已发生的官网注册不能因本地取消而撤销，恢复凭据仍保留。

## 验证范围

Node 单元测试覆盖加密、权限隔离、密码和 MFA 双重确认、任务锁、取消、幂等入池和 OAuth 失败恢复。Ubuntu 24.04 / Debian 12 的真实 Chromium 测试在 network-none 容器中拦截全部请求，以本地模拟页面覆盖统一邮箱入口、三次不同用途的邮箱验证码、接管恢复、密码失败阻断、密码确认后的恢复、TOTP 和邮箱核对。

这些测试没有真实注册或登录账号，也不证明当前官网页面的所有变体均可自动处理。流程基于用户反馈适配，不将某一种官网页面顺序写死；自动选择器主要适配中英文，其他语言、未知页面和额外验证可能需要人工接管。遇到已有账号的密码登录页不会填写新生成的密码；统一邮箱验证码入口可以继续，设置密码时若要求旧密码则暂停。不能确认密码与 MFA 完成的流程会暂停或报错，不会假装成功入池。
